## 根因与修复

1. 传输适配器此前把连接、超时、流中断等错误合并为相同提示，分析流程遇到任一错误立即结束。现在使用本地固定原因码区分可恢复故障、认证／请求错误、格式错误及输出预算不足；可恢复故障仅重试当前阶段，最多两次，每篇全部额外恢复尝试最多六次。退避支持取消，Retry-After最多30秒；每次失败调用都记录已知用量或未知部分。
2. 归纳正确拒绝漏引父事实，但无法纠正该分组。现在只对失败分组做一次有原文支持的纠正，使用短事实编号并反馈本地拒绝原因，重新检查每个父事实的引用、完整来源链和上下文压缩。成功纠正有独立缓存身份；再次使用仍在本地重验，未压缩成功的输出不留在可复用缓存中。
3. 卡片格式／章节错误此前直接留下缺口。现在对被拒绝的字段批量纠正一次，逐项重新核验引文和章节。空值、重复字段、范围外引文和对已通过字段的修改均不接受；整个修正卡片必须保留全部原有已核验条目、顺序和引用。纠正服务失败时保留已核验的部分卡片，不丢掉可用内容。
4. 界面区分“已纠正的条目”和仍未通过核验的条目；错误分类排除已解决的历史诊断。存在未解决问题的卡片仍为partial。

没有机械补齐缺失引用、放宽来源检查、循环反复问模型或把失败包装为completed。原抽取请求保持不变，可复用前次成功窗口；纠错和传输失败的额外费用不会藏在一次成功调用里。
