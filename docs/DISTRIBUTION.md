# 构建与发布

[文档目录](README.md) &nbsp;|&nbsp; [参与开发](../CONTRIBUTING.md)

本文面向维护者，记录当前 Windows x64 构建产物及其验收流程。日常使用从 [使用指南](USER_GUIDE.md) 开始。

在项目根目录运行：

```powershell
.\scripts\release.ps1
```

默认按上海日期分配版本，例如 `LIRA-2026.11.02.3-Windows-x64`。当天已有发布时递增末尾编号；不覆盖已有文件。需要明确版本号时：

```powershell
.\scripts\release.ps1 -Version 2026.11.03.1
```

同一工作区一次只允许一个发布流程。发布期间请勿修改源码，源码变化会在发布前被拦截。当前工作区的修改会进入构建；不要求 Git 干净，不自动提交、推送或上传文件。

## 发布机的准备

仅发布机需要 Windows x64、项目 `backend/.venv` 中的 Python 3.13、后端依赖、Node/npm、前端依赖、Playwright Chromium，以及已安装的官方 Codex Windows x64 包。先完成开发环境安装；前端与浏览器依赖可以这样安装：

```powershell
npm.cmd --prefix frontend ci
Push-Location frontend
npx.cmd playwright install chromium
Pop-Location
```

发布时复用已安装的依赖，不自动升级。首次构建需下载固定版本的 Python 嵌入式运行时及第三方许可。Python ZIP 校验固定 SHA256；模型调用不参与发布验收，不消耗个人额度。端口 8010/5177 用于隔离的模型设置回归；如果被别的测试占用，流程会失败并记录日志，不终止占用者。

## 自动执行的检查

| 阶段 | 验证内容 |
| --- | --- |
| 后端回归 | 发布边界、失败门槛、模型连接与并发、阅读优先、翻译队列及数据库迁移 |
| 设置界面回归 | 官方登录、模型能力目录、共享并发保存/刷新及窄窗口布局，使用隔离服务和测试响应 |
| 前端构建 | TypeScript 与生产构建，确保不用旧的前端文件 |
| 候选打包 | 源码允许清单、运行环境、官方 CLI、许可、文件 SHA256、私人数据与疑似密钥扫描 |
| 最终 ZIP 验收 | ZIP 校验码、路径和 manifest 完整性，再从实际 ZIP 解压启动 |
| 发布门槛 | 所有检查通过、测试服务停止、源码未改变，才复制到 dist 并更新 latest.json |

最终 ZIP 会被解压到中文含空格的新目录，数据放在本轮独立目录，PATH 只保留 Windows System32 并注入假继承凭证。检查包括：

- 首次论文、专题、模型配置为空，官方 CLI 可运行但未登录，继承凭证未进入应用。
- 占用首选端口后避让，同时和重复启动复用同一实例。
- PDF 导入、原文获取、阅读段落、专题和笔记，停止重启后仍保留；数据库完整性通过。
- 官方账号并发设置保存并在重启后保留，不进行真实登录或远端生成。
- 私人文件路径无法通过 HTTP 读取，未授权请求不能停止服务。
- 浏览器实际渲染 PDF worker，刷新后找到笔记，1440/1080 宽度无横向溢出，无页面错误或失败请求。
- 通过 finally 关闭本轮测试服务；不使用开发论文库或个人 LIRA 数据目录，不重启正式开发服务。

这是发布机上的隔离验收，不能替代另一台电脑、全新虚拟机或远端模型服务的实测。界面截图保留供维护者检查；自动检查布局与渲染，不评价视觉品味。

## 产物和交付

成功后 dist 目录包含：

| 文件 | 用途 |
| --- | --- |
| LIRA-版本-Windows-x64.zip | 可独立运行的应用包 |
| 同名 .zip.sha256 | 校验传输完整性 |
| 同名 .report.json / .report.md | 本轮阶段、检查结果、源码摘要和日志位置 |
| latest.json | 最近一次验收通过的版本、ZIP 名称和校验码 |

只发送 ZIP 即可；需要核对传输时附上 SHA256。不要直接压缩工作目录，也不要发送个人数据目录。分发包不含个人论文、笔记、对话、译文、密钥或官方登录状态。

使用者完整解压后双击「启动 LIRA.cmd」，无需 Python、Node 或 npm。在应用内配置自己的模型连接或登录自己的 ChatGPT Codex 账号。当前仅提供 Windows 10/11 x64 包；PDF 支持读取，CAJ 暂不支持直接导入，扫描件暂不支持 OCR。

## 失败与重试

命令会显示当前阶段及日志路径；完整诊断保存在 `.local-runtime/releases/<版本>-<本轮编号>/report.json`，每个阶段有独立 .log。最终包浏览器检查失败时还保留 verification/failure.png、ui-failure.json 和独立服务日志。

失败候选保留在这个忽略目录中，不进入 dist、不更新 latest.json。修复后重跑同一命令；同一版本的成功产物始终不会覆盖。没有跳过验收的正式发布选项。

底层 scripts/build_release.py 仅用于构建诊断；它本身不完成运行验收。单独生成 ZIP 不代表已经通过发布流程。`scripts/verify_release.py <ZIP> --work-dir <全新目录>` 可独立复验已有包，但不会更新 dist/latest.json。

## 使用者的数据和升级

数据保存在 `%LOCALAPPDATA%\LIRA`，包含数据库、原始 PDF、笔记、译文、问答、连接配置和独立官方账号。关闭浏览器后后台任务仍运行；双击「停止 LIRA.cmd」结束服务。

升级前先停止旧版并备份整个数据目录，然后将新版解压到新文件夹启动。新版自动迁移并沿用同一数据目录；不要覆盖正在运行的程序目录，不要同时运行两个版本，也不要用旧版打开已经升级的数据库。发布脚本保留旧 ZIP，但数据库降级不受支持。
