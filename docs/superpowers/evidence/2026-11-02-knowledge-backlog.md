# 知识整理积压统计与 SWE-smith 实测修复

## 复现与原因

用户在 Agent 初探专题看到大量待确认条目，AI 知识整理却显示待整理论文为 0。

- 原界面只统计最新同范围批次里的 `proposed / curate_paper`，漏掉导入时创建的单篇任务以及全库任务；已完成批次停止轮询。
- SWE-smith 有 47 个对象（40 个待确认）、32 条未确认关系，没有成功的正文整理记录；同一论文在三个单篇批次和一个全库批次重复排队。
- 后端忽略 `object_reviews.supported`，已有对象即使得到肯定结论，也没有完成身份确认，进而阻碍关系端点确认。
- 审阅上下文预算优先放入早期引用的邻近块，漏了 16 个直接引用块。
- 真实模型输出还暴露了别名命名空间冲突：一处冲突会让整篇写入失败。

## 修复

- 新增只读范围积压接口，跨批次按论文去重，区分等待检查、已检查仍有待确认条目，并分别统计对象和关系。
- 独立轮询范围积压；最新批次为空或完成也不会隐藏其他批次任务。
- 先应用安全的已有对象肯定决定，再处理关系；保留人工拒绝、别名修改和引文核验保护。
- 先供应直接引用原文，再填充邻近块；仍使用原有 20,000 字符审阅预算。
- 命名空间冲突局部回滚并保留待确认，其他有证据的决定继续写入。
- 排队读取最新知识快照；同篇相同快照跨范围复用检查结果，显式强制复查仍重新调用。
- 不把同一批次其他论文的失败信息挂到从未失败的论文下面。

## 真实运行

对现有 SWE-smith 执行一次真实官方模型检查，读取正文 38,321 字符及已有对象和关系的原始证据。模型检查了全部 40 个待确认对象和 32 条关系，生成耗时约 451 秒。

首份结果未直接通过引文校验。修复上下文供应后，仍有 7 项需要一次仅针对原始引文的模型复核；保存原始回复、补充原文和修复结果，全部再经严格原文验证。随后先在数据库副本应用，通过后才写回正式库。

写回结果：确认 28 个对象、15 条关系，排除 1 个无关对象，保留 74 条可撤销变更记录。剩余 13 个对象、17 条关系没有通过名称对应或端点等自动写入条件，继续显示待确认。这是一次完成检查后保留疑点的结果，不能宣称知识网络已全面整理完成。

三个重复检查任务复用本次结果，未再次调用模型。正文审阅的已捕获用量为输入 100,458、输出 17,097 tokens；引文修复调用的用量没有捕获，不能把以上合计当作完整计费总量。

部署后的 Agent 专题只读接口返回：7 篇待检查、8 篇存在成功检查记录、51 个待确认对象、58 条待确认关系；SWE-smith 明确标记为已检查仍有疑点。论文计数和条目计数并非同一个口径。

## 验证与保护

- 后端知识整理及后台调度相关回归：131 项通过；加入批次错误归属回归后，本次新增回归文件 11 项通过。
- 浏览器隔离测试：9 项通过，包含跨批次统计、完成后继续轮询、窄屏无横向溢出。
- 前端生产构建通过；存在原有大包体积提示。
- 正式运行页面已检查：Agent 专题显示 7 篇待整理、51 个待确认对象和 58 条待确认关系；SWE-smith 行为 13/17，状态为已检查仍有待确认条目。刷新后仍可见，520px 宽度没有横向溢出，没有浏览器异常，没有分析、翻译或提问模型调用。
- 正式数据库 integrity_check=ok，46 篇论文、34,189 个原文块；5 条个人笔记与写回前备份逐行一致。
- 部署时只暂停实际活跃的翻译队列并短暂关闭可选后台研究，等待模型活动为零；之后恢复原有研究、额度和并发设置，仅恢复由本次暂停的翻译任务。
- 原始模型输出、数据库备份、逐项引文修复、正式写回报告及运行截图保存在本机 `.local-runtime/smith-knowledge-audit/`，不进入发布包。

## 尚存边界

本次引文定向修复属于真实数据恢复，不是放宽引文验证，也尚未实现通用的自动引文修复流水线。剩余对象不能仅靠模型置信度强行确认；保留疑点和人工修改优先于把计数清零。
