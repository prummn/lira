# 专题后续研究：实现与实测

## 问题与改动

原来的调度在材料不变时只完成一篇文章和一批研究线索，之后便认为工作已完成。知识网络维护依赖程序找出的异常，不会主动深入研读。另有相同知识快照重复维护、把模型建议再次当成审计输入的问题。

现在基础整理之后可以继续规划 0–6 个具体问题，每项分别研读全文相关章节并核对原文，结果进入原有研究线索与修订历史。任务可以补充旧解释、纠正旧判断，也可以查阅后不发布新结论。每批任务有限，不递归产生子任务。

规划与研究继续使用唯一后台 worker 和官方连接。核验阶段优先完成；全文及章节元数据变化会使旧任务失效；规划结束、发送请求和发布结果时分别检查用户决定。定向深化强制更新指定的原条目，防止模型漏填 ID 后复制一份新线索。兼容早期任务时先检查父任务及全部子任务的原文，再采用新的全文指纹。

维护只处理原始审计问题，跳过已有成品的相同快照。所有研究和维护共享每小时预算，失败请求也计入尝试次数。

## 当前调度设置

本机已开启继续深入专题，闲置 60 秒后执行，每小时上限 36 次。短窗口启动线为剩余 50%，继续执行的停止线为剩余 35%，长窗口保留 30%。保持单并发，阅读、翻译与提问优先。

本轮检查点官方报告五小时已用 40%、周窗口已用 6%。这是账号窗口的现场读数；结果完成量以上表持久化记录为准。后两次服务更新都在无在途请求的检查点暂停后进行，已有研读和核验阶段继续使用；最初一次规划曾因开发期间重启中断，因此 Memory 规划记录有两次尝试，不能把它算作一次成功调用或自然抢占验证。
