# 固定 Windows 发布流程

用户已要求把刚完成的发布固化为可重复执行的流程，在当前工作区直接执行，不修改个人数据或正式服务。采用本地单命令流程，复用已有发布器和独立验收，不引入云发布或远端上传。

**目标：** `scripts/release.ps1` 自动分配上海日期版本，运行相关回归、前端构建、发布器、最终 ZIP 隔离验收；全部通过后才放入 `dist`，生成 SHA256、验收报告及 `latest.json`。

**文件职责：** `scripts/release.py` 负责阶段和发布门槛；`scripts/verify_release.py` 负责 ZIP 校验与独立运行验收；`scripts/verify_release_ui.cjs` 用浏览器验证最终构建；`scripts/release.ps1` 为 Windows 入口；`backend/tests/test_release_workflow.py` 验证失败门槛、版本、归档路径和不可覆盖约束。既有 `scripts/build_release.py` 保持底层打包入口。

- [x] 先补测试并观察失败：版本和覆盖保护、ZIP 路径与完整性、额外私人文件、失败不晋升、已验收产物发布。
- [x] 实现自动编号、互斥发布、阶段日志、失败报告、候选隔离目录和验收后晋升。新版本不覆盖旧包，默认完整验收，无跳过验收的正式发布开关。
- [x] 将之前临时验收脚本固化并参数化：路径含中文空格、系统 PATH、假继承凭证、空库、端口冲突、重复启动、PDF 导入阅读、笔记/专题持久化、模型设置、私有路径隔离，finally 关闭本次测试实例。
- [x] 浏览器验证阅读、PDF worker、笔记、刷新和 1440/1080 布局；失败捕获日志与截图；不进行真实模型生成。
- [x] 更新分发文档及 README，记录前提、产物、排错、升级备份和验证范围。
- [x] 从单命令实际跑完一轮新发布，检查报告、ZIP、开发服务和个人库均保持正确。

失败只保留 `.local-runtime/releases/` 中的诊断，不更新 `dist/latest.json`。运行目录和数据目录为本轮新建路径，不使用 `%LOCALAPPDATA%/LIRA` 或开发库。已有 ZIP 保持不变。验收结果只代表当前 Windows 主机，不宣称另一台电脑验证，也不把离线验收当作远端模型质量保证。
