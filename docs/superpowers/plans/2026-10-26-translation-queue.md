# Persistent Translation Queue Implementation Plan

**Goal:** 手选翻译边完成边读，重要论文可闲时预译，跨页面与重启保持任务。

**Architecture:** 持久作业和段落项共用现有翻译缓存，唯一后台研究 worker 按显式/闲时优先级执行。前端独立轮询队列，选择面板、当前译文及队列进度互不锁定。

**Tech Stack:** FastAPI / SQLAlchemy / SQLite / React / TypeScript / Playwright。

在现有工作区执行，保留原有未提交改动，不提交无关文件。使用 subagent-driven-development 分工实现明确边界，最后分别复核需求及代码质量。

- [x] 后端：先写并运行失败回归，新增模型/迁移、共享翻译缓存服务、持久队列与 API。
- [x] 调度：唯一 worker 接入手动和全文任务，完善阅读/前台抢占、每次调用额度检查与共享计数；验证边界合并与恢复。
- [x] 前端：实现队列 hook、逐段完成即可展开、待翻译标识、全文入口和暂停/继续/重试；不取消页面外任务。
- [x] 浏览器：第一段完成第二段等待时继续读、切换模式/论文/刷新后恢复、全文队列与窄屏；保留单段翻译回归。
- [x] 复核：需求检查、代码审查、全量后端及前端构建、相关浏览器测试。
- [x] 真实验证：在无在途调用的检查点更新服务，试跑官方翻译，核查持久缓存/任务/额度及界面，保存 evidence 与使用说明。

结果和验证范围见 [后台逐段翻译验证](../evidence/2026-10-26-translation-queue.md)。真实 MemGPT 全文预译已恢复，剩余内容由正常调度续跑，不把试跑记为全文已完成。
