# Codex 官方模型选择

目标：修复订阅连接中硬编码中转站模型与通用推理参数造成的错误，并让用户在应用内按当前官方 CLI 返回的能力选择模型。

已核对官方 app-server 文档：使用 `model/list`，模型、默认项和推理强度依账户及客户端而异，不能硬编码示例。本机 CLI 0.147.0 返回 gpt-5.6-sol、gpt-5.6-terra、gpt-5.6-luna；原有订阅配置为列表之外的 gpt-6.1-sol。另查明 WebSocket 连接超时，CLI 重试约 114 秒才回退到 HTTPS；直接使用官方 HTTPS 传输后，真实调用成功。

设计：使用官方目录的下拉选择，附默认标识、模型描述及刷新入口；推理选项随模型联动，提供跟随官方默认；新连接从目录选默认，旧的不可用模型保留并提示选择，不静默覆盖。账户登录和刷新后重新读取目录。请求前检查模型和配置强度，内部步骤的轻量推理只映射到该模型实际支持的级别；保存测试验证用户选定参数。

- [x] 先写并运行失败测试：目录分页、缓存、登录隔离/失效、过滤敏感字段、当前不可用模型及参数拒绝、max/ultra、实际测试参数、阶段推理映射。
- [x] 后端在 CodexAccount 增加安全目录及 GET /settings/codex/models；Codex transport 使用官方能力而非固定替换 minimal→low。
- [x] 前端拆出模型选择控件，处理登录、加载、空列表、失败重试、旧模型提示、刷新及编辑切换竞争；API key 配置保持自由输入。
- [x] 用浏览器测试默认选择、推理联动、旧配置、目录失败/重试、登录后加载、保存参数与无关连接切换；人工检查实际画面。
- [x] 解决真实调用超时；全量回归、构建、独立审查，更新 README，重启空闲服务。配置修复仅在已验证官方模型后进行，保留其他连接。

验证：后端 567 passed；浏览器 77 passed、2 个需额外开启的真实论文用例 skipped；生产构建和差异检查通过。独立审查修复了重复编辑的可保存状态、账户刷新同步目录，以及目录故障误记模型调用次数三个问题，复核无重要遗留项。

真实调用：Sol/high 11.0 秒、Luna/官方默认 9.4 秒完成；运行中应用的「测试并保存」16.2 秒完成。当前 Codex 配置已修为 gpt-5.6-sol/high，ID、主连接、备用顺序和其他连接保持不变。浏览器实际打开 5173，确认下拉目录、所选模型及 high 强度正确，无页面异常。
