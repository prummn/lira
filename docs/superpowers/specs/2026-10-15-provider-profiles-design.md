# 多供应商配置与 ReAct 分析恢复

用户已授权自主实现。目标：查明 ReAct 的实际失败并重跑；允许在应用内保存、编辑、测试、切换多份供应商配置，主动选择官方额度或中转站。

现有记录：ReAct 共 6 个全文窗口，第二次调用收到 HTTP 200 内嵌未知错误，被判为不可重试。不得根据这一条记录断言账户并发超限。

采用命名配置列表与详细编辑表单。配置包含地址、密钥、模型、协议、推理强度、超时、Chat 输出参数、JSON 模式和允许的同时请求数。保留现有配置，自动迁移为“当前配置”。主配置可一键切换；正在进行的单次请求完成后，后续请求使用切换后的路由。每次请求固定完整配置快照，不混用地址和密钥。

仅手动切换无法覆盖无人值守的长任务；无条件轮询则会把研究请求发往意外的服务。因此默认手动切换，提供显式开启的顺序备用列表：仅暂时性连接、限流、上游故障可使用备用。认证错误和无效请求直接报告；不自动降级模型。每个调用记录配置 ID、名称、模型和切换原因。原有窗口缓存按实际端点/模型/协议隔离。

配置及密钥存储在被 Git 忽略的本机配置文件，API 只返回 key 是否存在。旧单配置 API 保留兼容性。保存失败不改变运行状态。设置页不自动调用收费接口，测试连接为用户显式操作。

验证覆盖配置增删改、迁移/重启、密钥隔离、热切换、备用顺序、并发闸门、缓存和来源信息；用真实 ReAct 完整重试并检查覆盖率和科学复核结果。
